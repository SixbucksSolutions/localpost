# localpost v0.2.0

localpost is a shared loopback HTTP-to-file service for agents. This release
moves mailbox directory creation into the service and introduces explicit
API-date prefixes.

## Breaking API changes

- Provision an existing absolute root and start with `--mailbox-root <path>`.
  The listener defaults to `http://127.0.0.1:53147`; `--port` overrides it.
- Register with `POST /api/2026-11-05/registrations`, `Content-Type: application/json`
  and body `{}`. Localpost creates a UUIDv4-named directory and returns `id` and
  its absolute `directory`. The directory basename equals the registration ID.
- Send opaque bodies to `POST /api/2026-11-05/registrations/{id}/messages`.
  Retire with `DELETE /api/2026-11-05/registrations/{id}`.
- The caller-supplied `directory` request field is rejected. Retired unversioned
  routes and unsupported API dates return `404 unsupported_api_version`, with
  the supported prefix in the message. This includes preflight requests.
- Registrations are in memory. Restarting invalidates IDs, while directories and
  delivered files remain. Retire before cleaning up your owned mailbox.

Each API date identifies a fixed contract. Compatible fixes can retain the date;
future breaking contracts use a new date. One breaking revision per date is the
accepted limit. See the [versioned OpenAPI contract](https://github.com/SixbucksSolutions/localpost/blob/8783e38a27c6c07536c4c9e9c1d403b1cd39eb59/openapi.json).

Message delivery retains the 10 MiB body limit, 30-second stalled-read timeout,
opaque JSON/octet-stream bytes, UUIDv7 `.dat` filenames, complete-file publication,
wildcard CORS and best-effort semantics. Lost replies can leave delivery or mailbox
allocation uncertain. There is no automatic retry or durable registration queue.

## Deployment and permissions

The operator provisions the mailbox root. Windows service deployments use
inherited ACLs for LocalService and the agent account. The archive includes the
[pinned Windows service installer](https://github.com/SixbucksSolutions/localpost/blob/main/docs/windows-service.md),
which requires administrator installation and uses automatic startup, private
logs and a 40-second stop allowance. The daemon executable itself runs as an
ordinary user.

POSIX mailbox directories use `0700`, and delivery files use `0600`. Run the
service and consuming agent under the same UID. The
[container guide](https://github.com/SixbucksSolutions/localpost/blob/main/docs/containers.md)
covers host networking and a persistent root mounted at the same absolute host
and container path.

Docker image publication is the remaining release step. Its exact tested image
archives are retained and will be promoted without rebuilding.
