localpost is a shared loopback HTTP-to-file service for agents. It stores each
accepted message body unchanged in the caller's existing writable directory.

## Install and run

Verify the archive against `SHA256SUMS`, then unpack the complete archive into a
new directory. Run `localpost.exe` on Windows or `./localpost` on Linux as an
ordinary user. Go, Node/npm and the project's development tools are not required.

- `--version` reports the version, full source commit, Go version and build target
  without opening a listener. It must match the candidate identity above.
- The default endpoint is `http://127.0.0.1:53147`; use `--port` to select another
  unprivileged port. An occupied port fails startup instead of silently moving.
- Stop with Ctrl+C/SIGINT. Network drain has a 30-second grace period;
  filesystem calls can take longer. Coordinate active agents before restarting.
- Upgrade into a new directory and retain the previous executable/checksum for
  rollback. Registrations are ephemeral; agents register again after restart.

The archive contains offline instructions, licenses/notices, `build-info.json`
and the canonical `openapi.json`. The public [API reference](../../openapi.json)
and [README](../../README.md) describe requests, responses and limits.

## Behavior and compatibility

- One shared port with UUIDv4 registration paths; filenames use UUIDv7.
- Opaque `application/json` or `application/octet-stream` bodies, including empty
  and invalid-JSON-labelled data, up to 10 MiB per delivery.
- Wildcard CORS, plain loopback HTTP and no authentication.
- Best-effort, stateless delivery: no durable queue, replay, automatic retry,
  deduplication or power-loss durability guarantee.
- Complete-file publication requires a suitable hard-link-capable filesystem;
  unsupported publication fails rather than exposing a partial final file.

Clients of the early per-registration-port prototype must re-register and use
`POST /registrations/{id}/messages`; registration responses no longer contain a
port. Existing delivered files require no migration.

## Qualification and publication gate

Review evidence covers exact packaged bytes, ordinary-user execution, an empty
runtime PATH, port behavior, API/CORS and opaque delivery, partial/disconnected
uploads, no-clobber filesystem behavior, cleanup and SIGINT shutdown. Supporting
source collision tests are distinguished from observations made through the
packaged daemon. Windows and Ubuntu evidence must both pass independent review.

M06.04 publishes only this accepted artifact set. No last-minute rebuild or
substitution is permitted. This release does not automatically replace the
shared development daemon or install an updater/service.
