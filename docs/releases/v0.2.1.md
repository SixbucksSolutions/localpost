# localpost v0.2.1

**Status: development. Release qualification and publication are pending.** No
candidate identity, checksums, or qualification results are asserted here.

## Planned change

- Every daemon startup warns if the dedicated mailbox root has stale contents
  and removes all its children before serving HTTP. The daemon reserves its port
  first, so an occupied port fails before deletion. The root itself remains.
  This includes startup after either normal shutdown or forced termination.
- The operator must ensure only one daemon uses a root, even across different
  ports. There is no root lock. Keep unrelated data out of the root and copy
  needed deliveries elsewhere before restart.
- Unregistration retains the mailbox and delivered files until the next startup.
  Registration IDs remain ephemeral. The HTTP API and its `/api/2026-11-05`
  prefix are unchanged.

The published [v0.2.0 release](v0.2.0.md) retains root contents on restart.
Release artifacts and qualification evidence will be recorded when available.
